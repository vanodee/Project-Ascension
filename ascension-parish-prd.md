# Product Requirements Document

## Catholic Church of the Ascension — Parish Website

**Version:** 1.1
**Original draft:** May 2026
**Last reconciled with the codebase:** September 2026
**Location:** MMIA, Ikeja, Lagos, Nigeria
**Status:** Built — this document has been updated to describe the system as
implemented. `CLAUDE.md` and `README.md` are the day-to-day source of truth for
contributors; this PRD is the product-level overview.

> **Changes since the original draft**
> - **Online giving / donations removed.** The parish subcommittee rejected a
>   website-hosted donation feature. There is no `/give` route, no Paystack
>   integration, and no `donationCategory` schema.
> - **Parish schedule** is managed in Sanity (`recurringEvent` + `parishEvent`),
>   not Google Calendar. No Google Cloud project or API key.
> - **Livestream** is keyless — a server-side scrape of the channel `/live` page
>   plus the `videos.xml` RSS feed. No YouTube Data API v3 / API key.
> - **Sanity Studio** is hosted by Sanity at `ascension-parish.sanity.studio`,
>   not embedded in the Next app.
> - **Gallery** is photos only. Video support was scoped but never built and was
>   removed from the schema.
> - **Homilies** and **announcements** have no per-item `[slug]` route — both
>   render in an in-page modal / sticky player from their archive page.
> - **Resend** (transactional email) is not wired up; the contact form is a
>   Tally.so embed.
> - **Loomly / social-media review** is a parish-communications process outside
>   this codebase and is not part of the website.
> - `sitemap.xml` / `robots.txt` are generated by `app/sitemap.ts` /
>   `app/robots.ts`.

## 1. Project Overview

The Catholic Church of the Ascension required a modern, performant, and
maintainable parish website that serves its congregation and the broader public.
The site is easy to update by non-technical parish staff (all content lives in
Sanity), integrates with a small number of well-chosen third-party tools, and
reflects the dignity and identity of a Catholic parish.

**Primary Audiences:**

- Active parishioners seeking schedules, announcements, and resources
- New or prospective parishioners exploring the faith
- Visitors and the general public
- Parish administrators managing content

## 3. Tech Stack

| Layer | Technology | Notes |
|---|---|---|
| Framework | **Next.js 16 (App Router)** | SSG/ISR for SEO and performance; Turbopack build |
| Language | **TypeScript (strict)** | No `any`, full null checks (`noUncheckedIndexedAccess`) |
| Styling | **SCSS Modules** | BEM class names; mobile-first; design tokens in `styles/_tokens.scss` |
| CMS | **Sanity** | Hosted Studio at `ascension-parish.sanity.studio` (deployed via `npx sanity deploy`); the Next app only reads the content API |
| Media Storage | **Sanity native asset pipeline** | Images and audio on `cdn.sanity.io`; no separate media host |
| Calendar | **Sanity content** (`recurringEvent` + `parishEvent`) | Expanded to occurrences in `lib/calendar.ts`; no external calendar service |
| Daily Readings | **Universalis** (`africa.nigeria` calendar) | Free public JSONP endpoint, no auth |
| Liturgical calendar | **Computed locally** (`lib/liturgical.ts`) | Computus (Easter), Advent, seasons, Sunday A/B/C + weekday I/II cycles — no dependency |
| Forms | **Tally.so** | Embed only, no backend (RCIA inquiry + contact form) |
| Livestream | **Keyless YouTube** | Server-side scrape of the channel `/live` page + `videos.xml` RSS; `youtube-nocookie.com` embed |
| Linting | **ESLint 9** flat config | `eslint-config-next/core-web-vitals`; `next lint` was removed in Next 16 |
| Tests | **Vitest** | `lib/calendar.ts` occurrence-expansion suite |
| Hosting | **Vercel** | Push to `master` deploys production |

There is **no** payment gateway, Google Cloud project, YouTube Data API key,
transactional-email service, or social-media-management tool wired into this
codebase.

## 4. Information Architecture

```
/ (Home)
├── /about                      → About / Parish History (CMS-driven)
├── /clergy                     → Our Clergy (filterable directory)
├── /societies                  → Parish Societies Directory (search + type filter)
│   └── /societies/[slug]       → Single Society (hero, description, slogan, key info)
├── /readings                   → Daily Readings (Universalis)
├── /schedule                   → Parish Schedule (Sanity recurringEvent + parishEvent)
├── /announcements              → Parish Announcements (search + society filter; detail is an in-page modal, not a route)
├── /homilies                   → Homily Archive (search + priest/season/date filters; sticky inline audio player, no detail route)
├── /sacraments                 → Sacraments Overview
│   ├── /sacraments/rcia        → RCIA / Becoming Catholic (+ Tally inquiry form)
│   ├── /sacraments/baptism
│   ├── /sacraments/eucharist
│   ├── /sacraments/confirmation
│   ├── /sacraments/reconciliation
│   ├── /sacraments/anointing
│   └── /sacraments/matrimony
├── /livestream                 → Mass Livestream (keyless YouTube)
├── /gallery                    → Photo Gallery (search + society filter)
│   └── /gallery/[slug]         → Single Event Album (lightbox)
└── /contact                    → Contact Page (details, Mass times, Tally form, map)
```

Non-page routes: `/sitemap.xml`, `/robots.txt`, `/manifest.webmanifest`,
`/api/revalidate` (Sanity webhook receiver).

**Primary nav** (left → right): **About** (About & History, Our Clergy) ·
**Worship** (Daily Readings, Parish Schedule, Livestream) · **Sacraments**
(Overview + the seven pages) · **Societies** · **News & Media** (Announcements,
Homilies, Gallery) · **Contact**.

## 5. Feature Specifications

---

### 5.1 About / Parish History

**Purpose:** Provide the historical and spiritual background of the parish.

**Content managed via:** Sanity (`aboutPage` singleton)

**Page sections:**

- Hero image with parish name — **hard-coded** in `app/(site)/about/page.tsx`
  (not a CMS field)
- Rich-text narrative of the parish's founding and history (`body`, Portable Text)
- A scripture pull-quote (`scriptureQuote { text, reference }`)
- Up to four headline stats (`stats[] { value, label }`)
- Parish mission statement (`missionStatement`), rendered as a pull quote
- Milestones timeline (`milestones[] { year, title, tag, description }`)

**`aboutPage` fields:**

| Field | Type | Notes |
|---|---|---|
| `body` | Portable Text | Parish history narrative |
| `scriptureQuote` | Object | `{ text, reference }` |
| `stats` | Array (max 4) | `{ value, label }` |
| `missionStatement` | Text | Displayed as a pull quote |
| `milestones` | Array of objects | `{ year, title, tag, description }` |

---

### 5.2 Our Clergy

**Purpose:** Display photos, names, roles, and contact details of the parish's
clergy and catechists.

**Content managed via:** Sanity (`clergyMember`)

**Page layout:**

- Filterable grid (All / Priests / Reverend Sisters / Catechists)
- Each card: 3:4 portrait photo, name, title/role, contact info
- No dedicated per-member route — the grid is the whole feature

**`clergyMember` fields:** `name`, `slug`, `title` (e.g. "Rev. Fr.", "Sr."),
`role` (enum: `priest`, `reverend_sister`, `catechist`), `photo` (image + alt),
`bio` (Portable Text), `email`, `phone` (optional), `order` (display order).

---

### 5.3 Daily Readings

**Purpose:** Display the Roman Catholic daily Mass readings for the current day
(Lagos).

**Powered by:** Universalis — `https://universalis.com/africa.nigeria/{YYYYMMDD}/jsonpmass.js`
(JSONP; the wrapper is stripped and the payload parsed server-side in
`lib/readings.ts`). No auth.

**Displays:** date, liturgical season + colour badge, lectionary year, the
celebration(s) of the day, then First Reading, Responsorial Psalm (parsed into
structured refrain / verse / continuation / strophe-start lines), Second Reading
(only when present — Sundays / solemnities), and Gospel. Each reading shows its
scripture reference and full text; the Universalis copyright line is rendered
verbatim.

**Liturgical season, colour, and lectionary cycle** are computed locally in
`lib/liturgical.ts` (Computus for Easter; Advent / Christmas / Lent / Easter /
Ordinary Time; Sunday cycle A/B/C; weekday cycle I/II) — no external call.

**Freshness:** the fetch is cached until the next Lagos midnight
(`secondsUntilMidnight()`), with a 1 h segment-level backstop. On a fetch
failure the last successful payload is served from an in-memory cache.

---

### 5.4 Parish Schedule / Calendar

**Purpose:** Display parish activities — Masses, Confessions, novenas, events,
and meetings.

**Powered by:** Sanity content only. Two document types, edited in Studio under
**Schedule**, are expanded into concrete occurrences by `lib/calendar.ts`
(pure, tested) with the fetch in `lib/schedule.ts`:

- **`recurringEvent`** — a repeating rule: `frequency` weekly/monthly,
  `daysOfWeek` or `monthlyOrdinal` + `monthlyWeekday`, optional `durationMinutes`,
  optional `startDate`/`endDate` (season bounds), `active`. Per-date exceptions
  live in `overrides[] { date, mode: cancelled | modified, time?, location?, title?, note? }`.
  Start is either `startMode: 'fixed'` with a `"HH:MM"` Lagos `time`, or
  `startMode: 'follows'` with an `anchorEvent` reference + `anchorRelation`
  (`after` | `before` | `during`) — the occurrence's start is derived from the
  anchor's occurrence on the same date.
- **`parishEvent`** — a one-off dated event: `startDate`, optional `endDate`
  (multi-day), `allDay` toggle. Fixed `startTime`/`endTime`, or `follows` an
  anchor event on the same date.

**Event types** (colour-coded in the UI): `mass`, `confession`, `parish_event`,
`meeting`, `celebration`.

**Frontend views:** month grid + list view; filter by event type; event detail
in an overlay (title, date/time, location, description, any override note).
The homepage, contact, and livestream pages derive a "This Sunday / This Week"
Mass-times summary from the same expansion (`getScheduleWeek`).

**Freshness:** cached until the next Lagos midnight, 1 h segment backstop; also
busted on-demand when a `recurringEvent` / `parishEvent` is published.

### 5.5 Parish Announcements

**Purpose:** Publish timely notices, news, and updates.

**Content managed via:** Sanity (`announcement`)

**Features:**

- List page with cards: society-logo badge, title, date, excerpt, society-colour
  name tag. No image → a society-colour gradient with a default illustration.
- Live search (title, excerpt, event location, body) + a society filter dropdown
- Detail shown in a **modal overlay** (slides up from the bottom, focus-trapped,
  themed scrollbar) opened from the list card — **not a dedicated route**
- `expiresAt` — expired announcements are hidden from the frontend
- `pinned` — pinned announcements sort to the top regardless of date

**`announcement` fields:** `title`, `slug`, `excerpt`, `body` (Portable Text),
`image` (optional, + alt), `society` (**required** reference — use "Ascension
Family" for parish-wide content), `publishedAt`, `expiresAt` (optional),
`pinned` (boolean), `eventDate` / `eventLocation` (both optional). No `category`
field.

### 5.6 Homilies

**Purpose:** A searchable, filterable archive of priestly homilies with audio.

**Content managed via:** Sanity (`homily`); audio stored as a native Sanity file
asset.

**Features:**

- Archive page with live search + filters (priest, liturgical season, scripture
  reference, date range)
- A **sticky bottom player bar** plays the selected homily inline with a custom
  SCSS-styled HTML5 audio player; an info overlay shows the reflection body,
  scripture references, and the linked clergy record. **There is no
  `/homilies/[slug]` route.**

**`homily` fields:** `title`, `slug`, `author` (reference → `clergyMember`),
`publishedAt` (date of the Mass), `scriptureReferences` (string array),
`liturgicalSeason` (enum), `body` (Portable Text), `audioFile` (Sanity file
asset, `audio/*`), `audioDurationSeconds` (auto-filled on upload by a custom
Studio input).

### 5.7 Sacraments / Becoming Catholic

**Purpose:** Explain the sacraments and provide an RCIA inquiry pathway.

**Content managed via:** Sanity (`sacramentPage`); RCIA inquiry form via Tally.so.

**Structure:**

- **Overview** (`/sacraments`) — lists all seven sacraments with links
- **Seven individual pages** (`/sacraments/[slug]`) — `rcia`, `baptism`,
  `eucharist`, `confirmation`, `reconciliation`, `anointing`, `matrimony` —
  pre-rendered via `generateStaticParams`
- **RCIA page** (`/sacraments/rcia`) — embeds a Tally.so inquiry form via
  `tallyFormId`

**`sacramentPage` fields:** `sacrament` (enum slug key), `title` (page title),
`label` (nav label), `summary` (text), `heroImage` (image + alt), `body`
(Portable Text), `tallyFormId` (string — only set on the RCIA page).

### 5.8 Livestream

**Purpose:** Let parishioners watch Mass live, or the most recent recording.

**Powered by:** Keyless YouTube (`lib/livestream.ts`). No Google Cloud project,
no API key.

**Logic:**

1. Scrape the channel's public `/live` page — when the channel is broadcasting
   that URL resolves to a watch page whose canonical link is the live video, and
   the markup carries `"isLive":true`, title, and (best-effort) concurrent
   viewer count.
2. **If not live:** fall back to the most recent published video from the
   channel's `videos.xml` RSS feed.
3. **Graceful degradation:** last-known-good (in-memory) → hard-coded snapshot,
   so the page never errors.

**UI:** `youtube-nocookie.com/embed/{videoId}` iframe, a LIVE badge + viewer
count when live, plus a Mass-times summary derived from the schedule.

**Freshness:** ISR `revalidate = 60` (≈1,440 YouTube hits/day max); the
Mass-times block turns over at the next Lagos midnight.

**Config:** `NEXT_PUBLIC_YOUTUBE_CHANNEL_ID` (public). Streams must be started
as **Public** on YouTube — unlisted/private broadcasts are undetectable.

### 5.9 Gallery

**Purpose:** Showcase photos from parish events, organised and filterable.

**Content managed via:** Sanity (`galleryAlbum`); images on the Sanity asset
pipeline.

**Features:**

- Index page: event albums as cards (cover photo, society-logo badge,
  society-colour stripe, event name, date, description)
- Album page (`/gallery/[slug]`): focus-trapped lightbox photo viewer
  (arrow buttons + ←/→ keys)
- Live search (title, description, media captions and alt text) + society filter

**Photos only.** Video support (`videoItem`, YouTube embed) was scoped for v1
but never implemented end-to-end and was removed from the schema. If it's
revisited it should be built fresh (thumbnail derivation + an embedded player
reusing the livestream iframe idiom) — see `qol-ideas.md`.

**`galleryAlbum` fields:** `title`, `slug`, `eventDate`, `society`
(**required** reference), `coverImage` (image + alt), `description` (text),
`media[]` — `imageItem { image (+ alt), caption }` only.

### 5.10 Media Review

**Website media (gallery photos, homily audio):** Sanity's native Draft/Publish
workflow. Everything uploaded to Sanity starts as a **Draft** and is invisible
on the live site (`perspective: 'published'` on the read client); a Publisher
reviews and clicks **Publish** in the Studio. No additional tooling.

**Social media:** handled by parish communications outside this project. There
is no social-media-management integration in the website codebase, and
automated cross-posting from the site is explicitly out of scope (§11).

### 5.11 Contact Page

**Purpose:** Parish contact details and a simple way to send a message.

**Form:** Tally.so embed (`formId` `jagX9Q`).

**Page sections** (data from `siteSettings` unless noted):

- Address, phone (`tel:` link), email (`mailto:` link)
- Mass-schedule summary — "This Sunday" + "This Week", derived live from the

- "Send a Message" — Tally.so embed
- Embedded map to the parish

**Freshness:** ISR `revalidate = 3600`.

### 5.12 Parish Societies Directory

**Purpose:** Give the parish's zones, organizations, devotional societies, and
ministries a home, and let their name/logo/colour carry through wherever their
content appears (Announcements, Gallery).

**Content managed via:** Sanity (`society`)

**List (`/societies`):**

- Hero banner matching the site's other interior-page headers
- Live search by name; filter pills by society type, built from the types
  actually present in the data
- Responsive card grid — each card uses the society's own colour as its
  background, its logo in a circular badge, and a type badge + name on a
  frosted-glass panel; links to the detail page

**Detail (`/societies/[slug]`):**

- Split hero: left is the society's colour with its logo centred; right is a
  dark panel with the parish name, the society's name, and its subtitle
- Two-column body: description (Portable Text) + a bordered slogan strip
  (greeting/response call-and-response) on the left; a "Key Information" sidebar
  (Zone Patron / Established / Meeting Day / Zone Leader / Contact — whichever
  are present; Zone Leader and Contact may hold multiple values) on the right,
  bordered and icon-filled in the society's colour
- Closing CTA band linking to the About page

**Cross-cutting role:** every `announcement` and `galleryAlbum` has a required
`society` reference (the "Ascension Family" entry, `societyType: 'general'`,
covers parish-wide content). Their list pages use it for the society-logo badge,
society-colour accent, and society filter; publishing a society busts `/`,
`/announcements`, `/gallery`, and `/societies`.

**`society` fields:** `name`, `slug`, `societyType` (enum: `parish_zone`,
`demographic_organization`, `pious_devotional`, `charismatic_movement`,
`knightly_professional`, `liturgical_ministry`, `general`), `shortName`,
`color` (hex), `logo` (image + alt), `subtitle` (optional), `slogan`
(optional `{ greeting, response }`), `description` (optional Portable Text),
and a "Key Details" fieldset — `zonePatron` / `established` / `meetingDay`
(strings), `zoneLeader` / `contact` (string arrays).

## 6. Sanity CMS Schema Overview

| Document Type | Kind | Purpose |
|---|---|---|
| `aboutPage` | Singleton | About / Parish History content (history, quote, stats, mission, milestones) |
| `siteSettings` | Singleton | Parish name, contact details, social links, YouTube channel ID |
| `clergyMember` | Collection | Clergy / catechist profiles |
| `society` | Collection | Parish zones, organizations, and ministries — referenced by `announcement` and `galleryAlbum` |
| `announcement` | Collection | Parish announcements (required `society`, `expiresAt`, `pinned`) |
| `homily` | Collection | Homily records with audio (references `clergyMember`) |
| `sacramentPage` | Collection | Content for each of the seven sacrament pages |
| `galleryAlbum` | Collection | Event photo albums (photos only) |
| `recurringEvent` | Collection | Parish schedule — a repeating rule + per-date overrides |
| `parishEvent` | Collection | Parish schedule — a one-off dated event |

Studio structure and the singleton-template filter live in `sanity.config.ts`;
schemas are registered in `sanity/schemas/index.ts`. **After any change to
`sanity/**` or `sanity.config.ts`, redeploy with `npx sanity deploy`.**

## 8. Non-Functional Requirements

### Performance

- Lighthouse ≥ 90 on Performance, Accessibility, and SEO
- Core Web Vitals within "Good" thresholds
- Images served in next-gen formats via Sanity's pipeline + Next.js `Image`
- Static pages (About, Sacraments, Clergy, Societies list) built at compile time
- Time-sensitive pages use ISR (see §9)

### SEO

- Semantic HTML throughout
- `metadataBase`, canonical URLs, Open Graph + Twitter Card tags, and a
  `robots` directive set site-wide in `app/layout.tsx`
- `app/sitemap.ts` generates `/sitemap.xml` (static routes + Sanity slugs);
  `app/robots.ts` generates `/robots.txt`
- Both resolve the canonical origin via `lib/siteUrl.ts`
  (`NEXT_PUBLIC_SITE_URL` → `VERCEL_PROJECT_PRODUCTION_URL` → localhost)
- **Not yet done:** JSON-LD structured data for the parish as a `Church` /
  `LocalBusiness` entity; a purpose-built 1200×630 OpenGraph image
  (currently a 500×500 logo)

### Accessibility

- WCAG 2.1 AA target; keyboard navigable
- Sufficient colour contrast
- Alt text required on every Sanity image field
- Shared focus-trap hook (`lib/useFocusTrap.ts`) on all modal/overlay/lightbox
  dialogs (initial focus, Tab cycling, focus restore on close)
- Custom audio player with accessible controls

### Error handling

- `app/not-found.tsx` — branded 404 + unmatched-URL catch-all (no site chrome)
- `app/(site)/error.tsx` — error boundary for public pages, inside the site chrome
- `app/global-error.tsx` — last-resort boundary if the root layout throws
- Data-fetch helpers for the root layout (`getSiteSettings`), readings, and
  livestream degrade to cached/fallback data rather than throwing

### Security

- All secrets in environment variables; HTTPS enforced by Vercel
- Sanity read client uses `perspective: 'published'` — drafts never reach the site
- The revalidate webhook verifies the Sanity signature (`SANITY_WEBHOOK_SECRET`)
- Tally.so handles its own data compliance; no payment data touches the site
- No unnecessary collection or storage of personal data

### Responsiveness

- Mobile-first throughout; list view is the default for the schedule on mobile
- Touch-friendly gallery lightbox (swipe gestures are a backlog item)

### Hosting

- **Vercel** — native Next.js support, preview deployments, env-var management

## 9. Rendering & Revalidation

| Page | Strategy | Revalidation |
|---|---|---|
| About, Sacraments, Clergy, Societies (list) | SSG | Static build; on-publish webhook |
| Home | ISR | 10 min; Mass-times block turns over at next Lagos midnight |
| Announcements, Homilies, Gallery, Societies (detail) | ISR | 10 min |
| Contact | ISR | 1 h; Mass-times block turns over at next Lagos midnight |
| Parish Schedule | ISR | Next Lagos midnight (1 h backstop) |
| Daily Readings | ISR | Next Lagos midnight (1 h backstop) |
| Livestream | ISR | 1 min; Mass-times block turns over at next Lagos midnight |
| `sitemap.xml` | ISR | 1 h |
| `robots.txt`, `manifest.webmanifest` | Static | — |

All ISR pages also revalidate **on-demand**: a Sanity webhook posts to
`/api/revalidate` on publish (`app/api/revalidate/route.ts` maps each `_type`
to the paths it affects). The webhook's own GROQ `Filter` is a dashboard-only
setting on sanity.io/manage and must list every document type the route
handles.
